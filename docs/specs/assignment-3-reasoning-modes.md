# Задание 3: разные способы рассуждения

## Цель

Взять одну логическую, алгоритмическую или аналитическую задачу и решить ее через API четырьмя способами:

1. Прямой ответ без дополнительных инструкций.
2. Инструкция `решай пошагово`.
3. Сначала попросить модель составить prompt для решения задачи, затем использовать этот prompt.
4. Создать группу экспертов в prompt и получить решение от каждого.

После прогонов нужно сравнить ответы и определить, какой способ дал наиболее точный результат.

## Реализация в `llm_demo`

Демо использует более сложную PERT/CPM задачу про расписание проекта на 14 активностей.

Источник задачи и эталонного решения:

- https://cpm-pert.com/example-pert-cpm

```text
PERT/CPM задача: строительный проект из 14 активностей.

Даны активности, длительности в днях и непосредственные предшественники:

A Excavation — 2 — нет
B Foundation — 4 — A
C Walls — 10 — B
D Roof — 6 — C
E Exterior enclosure — 4 — C
F Interior enclosure — 5 — E
G Exterior walls — 7 — D
H Exterior painting — 9 — E, G
I Electrical — 7 — C
J Partitions — 8 — F, I
K Flooring — 4 — J
L Interior painting — 5 — J
M Exterior finishing — 2 — H
N Interior finishing — 6 — K, L

Найдите минимальную длительность проекта и критический путь.
```

Эталон:

```text
Минимальная длительность: 44 дня.
Критический путь: A → B → C → E → F → J → L → N.
```

UI оставляет один compact selector `reasoning_mode`:

| Mode | API-вызовы | Messages |
| --- | --- | --- |
| `direct` | 1 | только `user` task |
| `step` | 1 | `system` с инструкцией `Решай пошагово` + `user` task |
| `prompt_chain` | 2 | сначала `system` prompt-writer + task, затем solver получает generated prompt |
| `experts` | 1 | `system` с ролями аналитик/инженер/критик + `user` task |

## Сравнение

Backend делает простую авто-проверку под выбранную демо-задачу:

- найдено число `44`;
- найден путь `A-B-C-E-F-J-L-N`.

Score `2/2` означает совпадение с эталоном. Сравнение не является универсальным judge для любой задачи; если пользователь меняет task, авто-проверка остается привязанной к исходному эталону.

## Видимый ход рассуждения

OpenRouter может вернуть reasoning в `message.reasoning`, но только для моделей и провайдеров, которые это поддерживают. Поэтому UI показывает:

1. native reasoning из OpenRouter, если поле пришло;
2. иначе видимый расчет из ответа модели, если system prompt попросил блоки `ХОД РАССУЖДЕНИЯ` и `ИТОГ`;
3. для baseline без инструкций может быть только финальный текст.
