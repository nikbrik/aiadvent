# Задание 2: контроль ответа LLM

## Цель задания

Отправить **один и тот же user prompt**, но с разным уровнем контроля ответа. Сравнить:

- без ограничений (baseline)
- с ограничениями через **API-параметры**
- с ограничениями через **system message** (instruction-based)

**Результат:** один и тот же запрос с разным уровнем контроля — и наглядное сравнение «мягкого» (инструкции) vs «жёсткого» (API) enforcement.

---

## Ключевое решение по архитектуре

### User prompt — всегда один и тот же

Пример (демо-промпт про барista):

> Придумай 5 необычных причин, почему робот-бариста внезапно начал писать посетителям философские предсказания на стаканчиках. Ответь коротко, только список.

User prompt **не меняется** ни в одном из трёх режимов.

### Три режима (radio, не чекбоксы)

| Режим | User prompt | System | API-параметры |
|-------|-------------|--------|---------------|
| **Baseline** | один и тот же | — | только sampling: `temperature`, `top_p`, `top_k` |
| **API control** | тот же | — | + `max_tokens`, `stop`, `response_format` |
| **System control** | тот же | формат + длина + завершение | только sampling |

Radio вместо двух взаимоисключающих чекбоксов — понятнее для демо и видео.

### Почему не смешивать API + system в одном прогоне

- Чище сравнение: видно, **кто** контролирует ответ
- Не размывается вывод задания («контроль через API» vs «контроль через инструкции»)
- Проще объяснить в логах и на видео

## UI

### Блок 0: общее (как сейчас)

- Textarea **Промпт** (user message)
- Sliders: `temperature`, `top_p`, `top_k`
- Кнопка отправки

### Radio: режим контроля

```
○ Без ограничений
○ Контроль через API
○ Контроль через system
```

### Блок 1: API control (виден только при выборе «API»)

| Поле | Тип | Назначение |
|------|-----|------------|
| `max_tokens` | slider / number | жёсткий лимит длины генерации |
| `stop` | text input | stop sequences (через запятую или одна строка) |
| `response_format` | readonly / fixed | заранее заданное значение, напр. `{"type": "json_object"}` |

### Блок 2: System control (виден только при выборе «System»)

- Textarea **System message** с prefilled текстом (редактируемый для экспериментов)

**Prefilled system message (черновик):**

```
Ты отвечаешь строго по правилам:
1. Формат: нумерованный список из ровно 5 пунктов (1. … 2. … и т.д.).
2. Длина: каждый пункт — не более 15 слов.
3. Завершение: после пункта 5 сразу остановись. Не добавляй вступление, заключение и текст после списка.
```

System-режим закрывает **все три** требования задания текстом:

- формат ✓
- длина ✓ (семантическая, через инструкцию)
- завершение ✓ (явная инструкция, не API `stop`)

## Backend

### Текущее состояние (`llm_client.py`)

Сейчас уходит:

- `model`, `messages` (только `user`), `temperature`, `top_p`, `top_k`

### Что добавить

#### `messages`

- **Baseline / API:** `[{ "role": "user", "content": prompt }]`
- **System:** `[{ "role": "system", "content": system_message }, { "role": "user", "content": prompt }]`

#### API-режим — дополнительные поля body

```json
{
  "max_tokens": 120,
  "stop": ["\n6.", "\n\n"],
  "response_format": { "type": "json_object" }
}
```

Передавать только когда выбран режим «API control».

#### `server.py`

- Принимать из JSON: `control_mode` (`none` | `api` | `system`), поля API-блока, `system_message`
- Валидация: `max_tokens` > 0, `stop` — массив строк (парсинг из input)

## Смысл сравнения трёх режимов

| | Baseline | System | API |
|---|----------|--------|-----|
| Формат | как захочет модель | просим список из 5 | `response_format` / жёсткая схема |
| Длина | без лимита | «≤15 слов на пункт» | `max_tokens` — жёсткий потолок |
| Завершение | может добавить хвост | «после 5-го замолчи» | `stop` — обрезает генерацию |

**Вывод для демо:** инструкции задают *намерение*, API-параметры задают *границы*. System может быть проигнорирован; API режет даже mid-sentence.

## Отладка (порядок прогонов)

### 1. Baseline

Один прогон без ограничений. Зафиксировать:

- число пунктов
- вступление / заключение
- примерная длина ответа

### 2. System — 2–3 прогона

Смотреть **стабильность**: 5 пунктов? хвост? одинаковая длина при той же temperature?

### 3. API — по одному параметру

1. только `max_tokens`
2. + `stop`
3. + `response_format`

Так видно, что именно сломало/улучшило ответ.

### 4. `response_format`

- Не все модели на OpenRouter поддерживают одинаково
- Для `deepseek/deepseek-v4-flash` — проверить один раз
- Если API вернёт **400** — зафиксировать в демо: «не поддерживается»; fallback: формат через system или plain list без JSON
- Это валидный вывод задания: не все API-фичи универсальны

### 5. `stop`

- Подбирать под **реальный** формат ответа модели из baseline
- Кандидаты: `"\n6."`, `"6."`, `"---"`
- В логах смотреть `choices[0].finish_reason`: `stop` vs `length`
- Если модель пишет `6.` без `\n` перед ним — `"\n6."` не сработает

### 6. `max_tokens`

- Стартовые значения: baseline без лимита (или 512); constrained **80–120**
- Слишком мало + JSON = обрезанный/невалидный JSON — для демо может быть **полезной иллюстрацией** жёсткого лимита
- Подкручивать так: constrained укладывается в ~5 пунктов, baseline заметно длиннее

## Что логировать (для видео / отчёта)

Уже есть HTTP-логи в консоли. Дополнительно полезно из ответа OpenRouter:

- `choices[0].finish_reason` — `stop` / `length` / др.
- `usage.completion_tokens` — baseline vs constrained

Сравнение тогда не субъективное («кажется короче»), а с цифрами.

## Нюансы, которые мы обсудили

### «Один и тот же запрос» vs «контроль через API»

Задание смешивает два слоя, если всё дописывать в user prompt. Решение:

- user prompt **не трогаем**
- API-ограничения — в body запроса
- instruction-ограничения — в **system**, не в user

### System vs API — не «только формат»

System message описывает **формат + длину + завершение** — instruction-based control целиком. Это симметрично заданию по смыслу, различие — в механизме enforcement.

### `max_tokens` vs «длина в system»

- System: «5 пунктов по 15 слов» — **семантическая** длина
- `max_tokens`: **технический** лимит токенов

Модель может уложиться в 5 пунктов, но вылезти за `max_tokens`, или наоборот.

### `stop` vs инструкция «закончи после 5-го»

- API `stop` — принудительная обрезка
- System — просьба; модель может добавить «Надеюсь, помогло!»

---

## Narrative для видео (готовый сценарий)

1. **Baseline** — 5–7 пунктов, вступление, мораль в конце
2. **System** — обычно лучше, но возможны 6-й пункт, «Вот ваш список!», длинные строки
3. **API** — короче и резче; обрезка по `max_tokens` / `stop`; JSON может быть битым при малом лимите

**Главная мысль:** инструкции задают намерение, API задаёт границы.
